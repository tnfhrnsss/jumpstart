# 0002 · "마지막 푸시" 상태를 ahead 카운트로 추정

- 상태: 채택
- 맥락: Claude Code 디렉토리 목록에 폴더별 git 상태를 보여준다

## 문제
git은 **푸시한 *시각*을 따로 저장하지 않는다.** 그래서 "마지막으로 언제 푸시했나"는
정확히 알 수 없다.

## 결정
업스트림(추적 브랜치) 대비 **ahead/behind 커밋 수**로 상태를 추정해 표시한다.

- 앞선(미푸시) 커밋이 **0개** → `푸시 완료`. 이때 "마지막 커밋 시각"을 사실상 마지막
  푸시 시점으로 간주한다.
- 미푸시 커밋이 있으면 → `미푸시 N커밋`.
- 원격이 앞서 있으면 → `원격이 N 앞섬`.
- 업스트림이 없으면 → `업스트림 미설정`.

ahead/behind는 `git rev-list --left-right --count @{upstream}...HEAD`로 한 번에 얻는다.

## 왜
- 정확한 푸시 시각은 git만으로 불가능하고, 사용자가 실제로 궁금한 건 "지금 올라가 있나?"
  이므로 ahead 카운트가 그 의도를 가장 잘 대변한다.
- 외부 명령 호출은 메인 이벤트루프를 막으므로(`execFileSync` 동기) 호출 수를 최소화한다.

## 보안 메모
원격 URL을 UI·로그에 노출할 때는 **반드시 자격증명을 제거**한다
(`stripCreds`로 `user:pass@`/`token@` 제거, `toWebUrl`로 웹 주소 변환). 토큰/비번이
박힌 URL이 새어 나가면 안 된다.
